# 为什么没有继续扩建旧版留白

## 决策

从通用网页工作台转向原生Windows“续做卡”，不是因为原来的技术做不出来，而是因为功能重合后，继续增加笔记、任务、图谱并不能回答“为什么留下”。

## 看过的证据

- [Task Coach](https://sourceforge.net/projects/taskcoach/) 已有层级任务、笔记、提醒、时间跟踪。
- [QOwnNotes官方概览](https://www.qownnotes.org/getting-started/overview.html) 已有本地Markdown、Windows、脚本与浮动界面。
- [CherryTree](https://www.giuspen.net/cherrytree/) 已有文件/目录/网页引用和本地存储。
- [Ditto](https://sourceforge.net/projects/ditto-cp/) 已有持久剪贴板与全局入口。

这些页面实际获取过；GitHub/Gitee的直接仓库访问仍受工具限制，没有把官方介绍冒充完整仓库或许可证审计。没有复用这些项目代码，避免为一个窄流程搬进大型宿主和未知组件许可。

## 续页试图省掉哪一步

不是省掉保存或确认，而是省掉“我现在还得打开一个管理页、找到该写在哪、再回到刚才的工作”。

捕捉只要求一句下一步；标题可空。全局捕捉不显示主窗。保存落盘后可离开。回来按需选择资源，续做条留在工作旁；进展/完成不拉回主窗。用户始终控制资源是否打开。

## 为什么是独立Windows程序

- 不要求用户常开浏览器或安装另一套笔记宿主。
- 使用Windows真实热键、托盘、任务栏与可撤销Shell入口。
- 同一份数据在可見的磁盘目录，便于复制、备份和离开。
- 不把现有知识库搬来，不强迫标签分类和日常打卡。

## 没有交付的神话

不是全球首次，不保证比已配置好的旧工具更快，不恢复未保存窗口现场，不证明用户会长期留存。两小时产出的代码量也不是价值证据。

这版可留下来试的具体理由：**它已经能在真实Windows中完成那条窄流程，并经过磁盘故障、崩溃重启、原生交互、资源安全、打包和持续验证。** 至于是否减少你自己的中断恢复成本，需要在真实工作中用几次判断。

若只是多维护一份清单，就导出、卸载，继续用原工具。让退出也简单，是这个辅助工具的一部分。
